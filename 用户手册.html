1它是什么

一句话：给同一台电脑上的多个 AI 助手，共用一本记事儿的小本子。

记住长期偏好

「我以后希望周报先列结论，再列细节。」这类规则会跨会话留下。

换工具接着干

一个工具里确认过的项目决定，另一个工具能查回来，带原话。

能核对也能删

每条都有原话和来源；改、归档、永久删除都由你发起，删除有回执。

它不做什么

  • 不是自动接力。换工具后要你说一句「查一下」，记忆不会自己跳进新对话。
  • 不保证回答更准。测试版实测里，完整记忆的答对率低于模型自己写的交接笔记。它的价值在「少讲一遍」和「可核对」，不在「更聪明」。
  • 不做多设备同步。单人单机，多个宿主共用一份本机库；没有云端账号。
  • 不做本地小模型兜底。判断「值不值得记」要调用你配置的模型，会产生费用。
三个宿主，一套用法。安装步骤按宿主略有不同，但聊天里的话术、面板、数据格式完全一致。你可以在三个工具里说同样的话。

2装之前

先确认机器在表里，再看要花多少时间和磁盘。

平台能不能装说明
Windows 10 / 11 x64 + NVIDIA 显卡可以本机三宿主全链路实测过，这是当前最稳的组合
Windows 10 / 11 x64 + 核显可以装，未验完依赖和预制检查能过；首次编码在虚拟机上崩过一次，真实机器还没复现
macOS 15+ Apple Silicon引擎可用原生冷装与记忆引擎已验证；三个宿主在 Mac 上的桌面体验还没验收
macOS Intel装不上锁文件里没有对应的 PyTorch 包
Windows ARM / 32 位 / Linux不行没有轮子或未适配

你需要准备

磁盘约 8 GB（依赖 3.5 GB + 模型缓存 4.6 GB）。装在剩余空间不足 10 GB 的 C 盘容易失败。
时间首次装完到能用 10–20 分钟：依赖约 2 分钟，模型下载和首次编码约 4 分钟，其余是重启宿主和点信任。
模型账号一个 OpenAI 兼容的接口（base_url + api_key + 模型名），支持 Chat Completions 和 JSON 输出。国内常见供应商都可以。
宿主WorkBuddy / Codex / DeepSeek Harness，至少装一个；三个都装就三个都能用同一份记忆。
系统组件干净的 Windows 先装 微软 Visual C++ 运行库 x64，PyTorch 的 CPU 路径也需要它。
路径不要带中文和空格。解压到 C:\March7 这种路径最稳。带中文的路径在部分工具链上会出问题，排查起来很费时间。

3安装

四步。所有命令都在解压后的 March7 目录里执行。

第 1 步 · 解压

先新建一个空文件夹（例如 C:\March7），再把 zip 解压进去。压缩包里没有顶层文件夹，直接「解压到当前文件夹」会把一百多个文件铺在桌面或下载目录。

解压后这个目录里应该能看到 README.md、用户手册.html、pyproject.toml、src\、hosts\。看不到就说明解压位置不对。

第 2 步 · 装依赖

uv sync --locked --python 3.12

没装 uv 的话先装：Windows 用 powershell -c "irm https://astral.sh/uv/install.ps1 | iex"，macOS 用 curl -LsSf https://astral.sh/uv/install.sh | sh。装完重开终端。

期望结果：最后一行是 Installed …，退出码 0。第一次会下载约 3 GB，慢是正常的。

第 3 步 · 预检

uv run python scripts/doctor.py --preflight

它会逐项报「安装基础 / 完整写读依赖 / 各盘可用空间」，中文说明缺什么、去哪儿补。全绿再往下走；有 ✗ 就按它右边那句话修，不要跳过。

想连模型一起验（会下载权重、多花几分钟）：

uv run python scripts/doctor.py --preflight --probe-embedder
不想自己敲命令？把包目录里的 AI-SETUP.md 交给你常用的 AI 助手，说「按这个文件帮我装 March7」。这份文件写了每一步的命令、期望输出、退出码和失败分支，也写明了哪些事不能替你做（改依赖、删数据、回显密钥）。装完让它按里面的验收清单逐项跑一遍。

第 4 步 · 接入宿主

见下一节。三个宿主各装各的，装完都要完全退出再重开（只关窗口不算，配置在启动时快照）。

装完的目录长这样：src\March7\ 是引擎，hosts\ 是三个宿主的安装器，docs\ 是说明，用户手册.html 就是本文件——离线可看，双击即开。

4接入宿主

三选一、三选二、或三个都装。装哪个就在哪个工具里能用，记忆是同一份。

WWorkBuddy最完整

自动写入、开场带背景、一句话开面板，三样都有。

uv run python hosts/workbuddy/install.py --doctor
uv run python hosts/workbuddy/install.py --set-llm
uv run python hosts/workbuddy/install.py --apply
  • --doctor：只读检查四项，期望四行都 OK。
  • --set-llm：交互式填 base_url / api_key / 模型名，探针通过才落盘（详见第 5 节）。
  • --apply：一次写三处——钩子脚本、settings.json 的 hooks 块、mcp.json 的 March7 条目；任一失败整体回滚。

装完完全退出 WorkBuddy 再打开。第一次连到 March7 时，到「专家·技能·连接器 → 连接器 → 自定义连接器」点一次「信任」。

退出码：0 全绿；2 数据目录不可用或非空（加 --reuse 或 --data-dir）；3 解释器/包不可用（先 uv sync）；4 写入校验失败（已回滚）；5 模型探针失败；1 不是契约码——出现 1 说明有未预期的异常，把完整输出发给我。

CCodex

安装器同时写 notify（轮末写入）和 MCP 表（工具面），另加面板钩子。

uv run python hosts/codex/install.py --doctor
uv run python hosts/codex/install.py --apply

Codex 的 MCP 子进程不继承用户环境变量，只认 config.toml 里 [mcp_servers.March7.env] 那张表——安装器会替你写好。已有的绑定可以用 --panel-only 只刷新面板钩子。

换库要成对。MCP 配置和轮末钩子必须指向同一个目录。安装器已按同源处理；手工改过配置的话，改完完整重启 Codex，说一句「当前库和项目」核对。

DDeepSeek Harness

uv run python hosts/dsh/install.py --apply

默认 --mode profile：开场注入画像，聊天里能开面板、能明确补记。另有 --mode turn（每轮召回，实验性）和 --mode none（只装工具面）。

DSH 没有轮末写入钩子：要它记，就在聊天里明确说一句「帮我记住……」。

三个都装？

可以。三个安装器默认都指向同一个数据目录（~/.March7），所以记忆天然共用。如果给某个宿主单独指定了 --data-dir，记得另外两个也指到同一个目录，否则会出现「A 记的 B 查不到」。

卸载：install.py --uninstall（三个宿主各有）。只移除它自己写的条目，你自己的键一个不少；钩子文件是移走不是删除。卸载不动记忆库。

5配置模型（API key）

March7 用你选的模型判断「这句值不值得记」、遇到冲突时裁决。没有 key 也能装，但写入会失败。

填什么

项说明
base_urlOpenAI 兼容端点，通常以 /v1 结尾。例如供应商文档给的 https://api.example.com/v1。
api_key你的密钥。只写进宿主的配置文件，不进仓库、不进日志。
model模型名，按供应商文档填。建议选便宜、支持 JSON 输出的型号——它每轮只做分类判断。

怎么填

uv run python hosts/workbuddy/install.py --set-llm

按提示输入三项，它会发一次很小的请求验证连通性。探针失败就一个字节都不写，旧配置原样保留。也可以一次传参（适合脚本）：

uv run python hosts/workbuddy/install.py --set-llm --llm-base-url "https://api.example.com/v1" --llm-model "your-model"

换了 key 怎么办

WorkBuddy 重跑一次 --set-llm，通过后完全退出并重启。多宿主用户要分别对齐：

  • Codex：工具配置和自动写入用的进程环境是两套，重跑 hosts/codex/install.py --apply。
  • DSH：重新应用插件配置。
  • 一次改齐四处副本：uv run python scripts/rotate_llm_key.py。
不要把 key 贴进反馈。截图、日志、配置文件都先删掉 key 和私人内容。

6第一次验证

三步。过了这三步，才说明「写入 → 存储 → 召回」整条链路通了。

① 工具连上了吗

在任意已接入的宿主里：「调用 March7_status 看一下状态」

返回 march7_version、db_schema_version、memory_count。看不到这个工具，说明宿主没连上——回去检查是否完全重启、是否点了信任。

② 写得进去吗

说一句低敏事实：「帮我记住，我每周日早上参加青苔星钟合奏。」

回答结束后等几秒（后台写入）。然后在安装目录运行下面这行，能看到这条就说明写成功了。

uv run python -m March7.control list

③ 找得回来吗

「帮我查一下青苔星钟」

回复里有这条记忆、匹配理由和原话。换一个宿主、同一个项目目录再查一次，能看到同一条，接力就成立了。

列表是空的？先跑 uv run python -m March7.control why --last，它会告诉你这一轮为什么没写：模型判定不值得记、被过滤规则拒收、还是请求失败。

7用说话管记忆

这一节是日常主路径。标 实测 的句子，是 2026 年 11 月在三宿主里真实说过的；方括号里是可替换的示例内容。

记一条

「帮我记住，我以后希望周报先列结论，再列细节。」

回复会说明实际补记了什么。工作流类、偏好类、项目决定最适合；一次性任务（「帮我改这段代码」）不会被记。

「在 March7 测试记忆库里，把『周末住在杭州』改成『只在每年七月住在杭州』」实测

明确点出库名或项目、用引号给出目标，识别率最高。改完旧版留在历史里。

查回来

「用 March7 查一下这个项目上次定了什么，把原话一起给我。」

返回条目 + 来源原话 + 适用条件。没有命中时会直说「没找到」，不会编。

「帮我搜一下『青苔星钟』」

按关键词找，适合你记得字面、不记得语义的时候。

「当前库和项目」实测

返回库编号、路径和项目假名。跨宿主对不上号时，先问这一句。

改、归档、恢复

「把这条改成『我用黄册记录演练步骤』」

纠正会新建版本，旧原话进历史。同名多条时先报「第几条」或补一句能区分的文字。

「把这条记忆归档」实测 / 「还原刚才那条」

归档后不再参与普通召回，但能在面板「历史」里找到并恢复。

删掉

「忘掉这条」

先显示永久删除预览（正文 + 作用域）。核对后另发一条「确认删除」或「取消删除」。

授权边界：预览只对同一聊天、同一项目、同一版本有效。换了聊天、说了别的请求、条目变了或超过时限，都要重新查一次。永久删除无法撤销，但会留一张不含正文的回执。

「查看擦除回执」

回执记录范围、条数、验证状态，不含被删正文。回执只能证明 March7 覆盖的范围——旧导出、备份、宿主原对话、模型服务商日志要分别处理。

记忆体检与批量整理

记忆多了会出现同义重复、旧版残留、错归项目的条目。体检就是一次性把它们找出来，给你一份可确认、可撤销的整理方案。

「帮我检查个人记忆」实测 / 「检查当前项目记忆」

返回几组候选：同义重复、相关但独立、有证据支持的更新、待复核。每组带编号。

「按返回的组号，生成记忆整理预览」实测

给出草稿编号（形如 M7-…）和「将归档哪几条、保留哪几条」。此时还没动库。

「确认个人记忆整理，批次号 M7-……」实测

执行，出整理回执。不想执行就说「取消个人记忆整理，批次号 M7-……」。

「预览撤销个人记忆整理，回执号 R-……」实测

给出撤销预览，确认后原批标记为已撤销，被归档的条目恢复。

「开启个人记忆自动体检」实测 / 「关闭个人记忆自动体检」

默认关闭。开启后按范围复用上次结果，只在相关条目变化时重查。

导出

「请导出我的记忆」/「导出记忆为 JSON」

回复给条数和文件路径。导出文件含原话，分享前先看内容。

问它为什么

「为什么没记住」/「为什么用了这条记忆」

显示筛选原因、计数和预算。比翻日志快，也安全（只读，不调模型）。

8记忆面板：手动操作

不想用说话的时候，所有事都能在面板里点。面板是本机网页，只监听 127.0.0.1。

怎么打开

  • 在聊天里说：「打开 March7 记忆面板」（也认「开启 March7 记忆面板」）实测
  • 双击入口：数据目录里与记忆库同放的 March7 记忆面板.cmd（三个宿主的安装器都会放一个）
  • 再打开：会复用已经跑着的服务，不重复起进程；会话过期后从原入口重开
面板打开的是「安装时绑定的那个库」。想看得另一个库，用「设置与切换库」，不会改变宿主绑定的库。

六个分区

分区里面是什么能做什么
个人记忆跨项目通用的长期事实、偏好、规则搜索、查看详情、纠正、归档、永久擦除
项目带项目身份的进度与决定（按项目分开）同上，另可切换项目范围
画像从长期事实里提炼的画像字段只读查看；改画像要回聊天里提供原话
历史被纠正、归档、过期的旧版本核对旧原话、恢复归档条目
擦除回执每次永久删除的范围、条数、验证状态只读核对，不含被删正文
设置与切换库二次提醒开关、打开另一个已有库分别关闭纠正/擦除的二次提醒；切库不改宿主绑定

找一条

  1. 搜索框输入正文、原话里的词，或直接贴记忆编号；
  2. 用状态下拉（有效 / 已归档 / 已过期 / 已被替代）和项目范围缩小；
  3. 点「查看详情」：原话、来源版本、写入时间、适用期限、作用域。

改一条

详情页点「纠正」，输入一条完整的新事实（不是补丁）。提交后新版本生效，旧版进「历史」，随时能对照。默认要再确认一次；可以在设置里关掉提醒，但点了就是提交。

归档 / 恢复

归档 = 暂时停用，不参与召回也不出现在默认列表，但没删。到「历史」里找到它点「恢复」即可。适合「这个偏好先放放」。

永久擦除

  1. 详情页点「永久擦除」；
  2. 核对预览里的正文和作用域；
  3. 确认后立即执行，没有恢复按钮；
  4. 到「擦除回执」核对结果。
擦除只覆盖 March7 自己存的那份。之前导出的文件、宿主自己的对话记录、备份、模型服务商的日志，都要各自处理。

记忆体检（面板版）

面板里点「记忆体检」，选个人或某个项目，看到的就是聊天里那句「帮我检查个人记忆」的结果。可以在这里看草稿、核对原话，再回聊天确认——两边读的是同一份状态。

批量整理与撤销

整理方案带草稿编号，执行后出回执；按回执可以生成撤销预览。换库、换范围、条目变化或超时后，旧方案失效，需要重新生成——这是防「拿着旧方案改错东西」的护栏。

9三个宿主的差别

同一套引擎、同一份记忆；差别在「谁负责写」和「开新会话时带不带背景」。

能力WorkBuddyCodexDeepSeek Harness
自动写入每轮结束尝试每轮结束尝试（notify）不做，要你明确说「帮我记住」
开场带背景有（会话启动注入）没有注入通道有（插件注入系统提示）
主动查可以可以，但要它主动调工具可以
一句话开面板原生入口已信任的原生入口原生入口（profile / turn 档）
装机步骤3 处配置2 处（同一文件）1 处（插件补丁）
已知坑安装时若已有别的插件共用 settings.json，安装器只剥离自己的条目notify 是单值，和 computer-use 之类会冲突；换库要成对写入依赖模型调工具，不会自己记

怎么做一次接力

  1. 在 A 里把事说清楚（偏好、决定、进度）；
  2. 换到 B，打开同一个项目目录（项目记忆按目录识别）；
  3. 在 B 里说「当前库和项目」核对库编号，再说「用 March7 查这个项目上次定了什么」。
项目身份是门槛。没有可信项目身份时，项目事实会拒写，而不是悄悄写进「全局」。所以换目录后如果发现「查不到」，先确认两边真的是同一个项目目录。

10出问题怎么办

先按症状查表；查不到再跑三条自查命令。

症状常见原因怎么修
装依赖时报找不到 torch当前架构没有对应轮子对照第 2 节平台表；确认是 x64 不是 ARM
--apply 退出 2，说目录非空之前装过加 --reuse 复用，或 --data-dir 换新库
退出 5，探针失败key 无效 / 余额 / 端点不兼容重跑 --set-llm，确认 base_url 以 /v1 结尾
工具列得出来，一调就报配置错key 没进宿主配置重跑 --set-llm，完全重启宿主
说了事实但没记住任务指令 / 模型判定不值得记 / 余额control why --last，一行告诉你原因
想不起昨天说的关键词降级、项目不一致doctor.py 看 vec 是否 ready；问「当前库和项目」
每次等很久无独显时 CPU 编码慢正常，首次约 10–15 秒；doctor.py 会写预估
面板打不开 / 打开了空库服务没起、或看了另一个库从原入口重开；面板里看「设置与切换库」当前指向
Codex 看到的库不对自行启动时 MCP 与钩子不是同一目录重跑安装器，完整重启，问「当前库和项目」

三条自查

# 1. 环境与模型是否就绪
uv run python scripts/doctor.py

# 2. 上一轮为什么没写

# 3. 库健康与残留
uv run python -m March7.control health
反馈时贴什么：完整命令 + 完整报错 + 退出码。别贴 key、别贴私人正文。

11隐私、数据与卸载

数据在哪儿

内容位置离开本机吗
记忆库（SQLite）~/.March7/March7.db不会
画像~/.March7/profile.json不会
写入账本与日志~/.March7/logs/不会
要判断的对话原文每轮结束时发给模型会
命中的记忆每轮开始时随宿主上下文会（发给宿主用的模型）

最后两行是核心事实：用哪家模型，就等于把那部分内容交给哪家。这一点无法用本地代码消除。

停止使用

uv run python hosts/workbuddy/install.py --uninstall
uv run python hosts/codex/install.py --uninstall
uv run python hosts/dsh/install.py --uninstall

卸载只移除 March7 自己写的配置，不动记忆库。想连数据一起清掉，先决定要不要导出，再执行：

uv run python -m March7.control erase --all

两件事刻意分开：卸载是「不想用了」，删数据是「忘掉我」。

12反馈

填随包的 首测反馈：四道单选题，不到 3 分钟。最要紧的三件——

  1. 哪一步卡住了：贴命令 + 完整报错；
  2. 它记错了什么：比漏记严重得多；
  3. 删了之后还能不能搜到：这是硬承诺，残留即 P0。

填完发回给发你测试包的人；就在聊天里的话，直接贴过去也行。
