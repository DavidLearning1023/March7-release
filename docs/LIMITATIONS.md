# 已知局限（0.1.0 测试版）

> 这份清单是发布物的一部分，不是免责声明。挑进这里的标准只有一条：
> **会不会影响你判断"这东西现在能不能用"**。
> 数据截至 2026-11-24。内部评测记录里有逐条复算过程，本页只放结论与数字。

## 一句话结论

**0.1.0 的记忆召回准确率不高于"把完整对话交给模型"这种朴素做法。**
它的价值在另外三件事：跨工具拿到同一份记忆、每条都能追溯原话、能授权删除并拿到回执。
**不是**"比模型自己记得更准"。

## 1. 准确率低于不装

| 口径 | 准确率 | 说明 |
|---|---|---|
| 装上插件（`full`） | **0.7963** | 合成语料 HANDOFF-128，单次运行 |
| 只用长期记忆、关掉推理注入 | 0.8796 | 同一批语料 |
| 裸宿主（不做任何记忆处理） | **0.9136** | 同一批语料 |

装上插件后反而更低。直接原因是注入挤占了上下文预算（见第 2 条），
不是检索找不到——同批实验里检索召回率是够的。

## 2. "压缩"这个卖点不成立

`full` 臂平均注入 **424 字**，而它引用的原始证据只有 **316 字**。
想让模型少读点字，结果是多读。这一条在当前数据集上被反复复现，不是偶发。

## 3. 写入侧质量

- 人工校准 **κ = 0.919**（200 条分层抽样）：误记 **4.6%**、漏记 **4.6%**。
- 更早一版口径是 κ = 0.929 / 误记 3.5% / 漏记 4.6%，两个版本的数字要一起看。
- **已知静默丢失**：模型会把约 **1/7** 的"稳定看法"误判成一次性请求而丢弃。
  这类丢失事后查不出来——库里就是没有这条，不是标错了。

## 4. 判分器本身有误差

- 判分器与人工的一致性是 **κ = 0.8695**（n = 200）。
- 假阳性 **6.5%**（7/107）、假阴性 **6.5%**（6/93）。
- 所以本页所有准确率都带这个误差带，**不是无误差真值**。
  两处 κ 是两件事：0.919 管"记得对不对"，0.8695 管"答得对不对"。

## 5. 语料边界

- 主评测集是**合成的**：12 个人物、120 段会话、324 条，用 API 模拟而非真实宿主在环，
  单次运行、无置信区间 ⇒ **不能外推到线上表现**。
- 真实语料只有 **20 条**（REAL-20，单用户）：一条题就是 5 个百分点。
  最近一批 `full` 臂是 **0.4500**（9/20，单次重复）。
  该批没有重跑"模型代写交接笔记"对照臂，因此不与更早批次的 0.8500 做同批比较。
- 写入策略与模型换过几轮，**不同批次的数字不可横比**，引用时必须整批换。

## 6. 项目隔离只对新写入生效

- 只有新写入的记忆会带项目身份；历史遗留的全局条目**不做回溯迁移**。
- 历史会话的首次观察、宿主未提供会话身份、旧库里已经分裂的目录映射，
  这三类情况缺少自动对账依据。

## 7. 延迟

- 每一轮都要先做一次 LLM 判断决定记不记，最坏路径约 **42 秒**。
  这个数是按超时预算算出来的，**没有做真机端到端计时**。
- 截止是非抢占式的：一条 LLM 调用要跑满 20 秒才会收口，不能中途打断。

## 8. 平台

| 平台 | 状态 |
|---|---|
| Windows 10 / 11 x64 | 本机宿主已验证，无 NVIDIA 冷装待验 |
| macOS Apple Silicon | 引擎 ARM64 冷装已验证，桌面宿主待验 |
| macOS Intel、Windows ARM、32 位 | 锁文件缺对应 PyTorch 包，**装不上** |
| Linux x64 | 未验证 |

## 9. 功能边界

- **不做云同步**：换电脑要自己搬数据目录。
- **不做多人共享**：单用户单机。
- **擦除只覆盖 March7 自己的库**：宿主原对话、已导出的文件、你的备份、模型供应商的日志，
  需要分别处理。回执会写明覆盖范围，别把它当成"全删了"。

## 10. 尚未验证的

- 第三方真人试用（原计划由非开发者本人完成一遍删除流程）。
- 人工盲评的一致性（那批 1,536 条次只有判分器结论，没有人工标签）。
- 跨项目零泄漏：写入侧已经修了，但评测建库不传项目身份，
  所以这件事**还没有在真实数据上被检验过**。
